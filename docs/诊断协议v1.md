# 诊断协议 v1

Peek Desktop 与 `peek_desktop_bridge` 使用本协议同步普通日志和异常。标准网络连接仍使用 Peek remote protocol v1，路径为 `/`；诊断使用同一监听端口下的独立路径。修改本文件时，同时更新桌面和 SDK 仓库中的副本。

## 能力探测与连接

`GET /diagnostics/v1/capabilities` 返回 `protocol: "peek-desktop-diagnostics"`、`version: 1`、`serverId` 和能力数组，不返回配对凭据或记录。

客户端连接 `ws://host:port/diagnostics/v1`，在 10 秒内发送 JSON 文本握手：

```json
{
  "type": "diagnostics.hello",
  "protocol": "peek-desktop-diagnostics",
  "version": 1,
  "serverId": "desktop-demo",
  "deviceToken": "<已配对设备的凭据>",
  "runId": "run-demo",
  "networkSessionId": "<当前网络会话ID>"
}
```

`serverId`、`deviceToken` 和 `networkSessionId` 取自同一官方 `PeekRemote` 的公开 API；`runId` 由 SDK 创建。诊断复用配对结果，不再次提交配对码。

成功返回 `diagnostics.welcome`，包含 `protocol`、`version`、`runId` 和 `accepted`。`accepted` 是 emitterId 到已接纳序号字符串的映射。失败返回 `diagnostics.denied` 和 `reason`。

非空 `networkSessionId` 必须属于该设备且当前在线；空值创建独立诊断运行。同一设备和 run 重连时不能改绑网络会话。网络连接关闭、替换、服务停止或设备被忘记时，对应诊断连接关闭；单独关闭诊断权限不影响网络。

## 事件字段

| 字段 | 类型与含义 |
| --- | --- |
| `eventId` | 非空字符串，事件身份，重试时保持不变 |
| `runId` / `emitterId` | 非空字符串，App 运行与发送源身份 |
| `sequence` | 规范 uint64 十进制字符串，发送源内从 1 递增 |
| `occurredAt` | 以 `Z` 结尾的 RFC 3339 UTC 时间 |
| `monotonicMicros` | 可空的 uint64 十进制字符串，同一运行源内的相对时间 |
| `kind` | `log` 或 `exception` |
| `level` | `verbose`、`debug`、`info`、`warning`、`error`、`critical` |
| `source` / `tag` | 非空来源字符串、可空标签字符串 |
| `message` | 消息字符串 |
| `attributes` | 可空 JSON 对象，已经规范化和脱敏 |
| `exception` | 异常对象，`kind: exception` 时必需 |
| `relatedNetworkEntryId` / `traceId` | 可空字符串，由采集方显式提供 |
| `truncated` / `truncatedFields` | 裁剪标记和字段路径列表，默认 false / 空列表 |

异常对象的 `stackTrace` 为必需字符串，可以为空；`type`、`message`、`stackFormat` 可空。序号和单调时间不允许符号、前导零或超过 uint64 范围的值，单独的 `"0"` 是合法十进制表示。

以下事件可用于协议测试：

```json
{
  "eventId": "run-demo/main/1",
  "runId": "run-demo",
  "emitterId": "main",
  "sequence": "1",
  "occurredAt": "2026-11-13T03:00:00.000Z",
  "monotonicMicros": "2500000",
  "kind": "exception",
  "level": "error",
  "source": "demo",
  "message": "测试数据解析失败",
  "attributes": {"operation": "parse"},
  "exception": {
    "type": "FormatException",
    "message": "Invalid test payload",
    "stackTrace": "#0 parseDemo (demo.dart:10:3)\n#1 main (demo.dart:20:5)",
    "stackFormat": "dart"
  },
  "truncated": false
}
```

墙钟时间用于跨来源时间线，不用于推断因果关系。只有同一绑定网络会话中明确引用且仍保留的请求可作为准确关联；按时间查找的记录显示为附近请求。

## 批次与累计确认

`diagnostics.batch` 包含 `emitterId` 和 `events`。每批 1–64 条，整个消息最多 256 KiB，单事件最多 128 KiB；一个 run 最多 16 个 emitter。

事件的 `runId`、`emitterId` 必须与连接及批次一致。服务端校验整个批次后原子接纳；重放已接纳序号不会重复展示，新序号复用已有 eventId 或同批序号冲突会被拒绝。

`diagnostics.ack` 返回 `emitterId` 和 `sequence`，累计确认该发送源的连续接纳位置。SDK 同时只保留一个待确认批次，重连后根据 welcome 的 `accepted` 重试队列中的事件。

ACK 表示内存接纳，不表示磁盘保存。归档和恢复快照不改变 ACK 的含义。

## 缺口、错误与心跳

SDK 已淘汰部分序号时，先发送 `diagnostics.gap`，字段为 `emitterId`、`fromSequence`、`toSequence`、`reason`。范围必须覆盖服务端下一个期待位置。服务端记录新增缺口，再 ACK 到 `toSequence`；重复 gap 不重复计数。

非法诊断消息返回 `diagnostics.error` 和 `reason`，未知消息忽略。`diagnostics.ping` / `diagnostics.pong` 用于心跳，60 秒无输入关闭连接。诊断错误不会关闭标准网络连接。

## 容量

桌面最多保留 8 个诊断运行，每运行 2,000 条 / 4 MiB 原文，优先淘汰低级别日志。高等级日志和异常也有硬上限。接收、去重、淘汰和缺口分别计数，最近 64 个 gap 范围可查询；展示淘汰不回退已确认序号。

SDK 默认待发队列同样为 2,000 条 / 4 MiB；每 50 ms 或累计 64 条触发发送，单批再限制为 240 KiB。转换、脱敏和裁剪在入队前完成。切换电脑或重置账号上下文后，旧连接任务与 ACK 失效。
