# 诊断协议 v1

本契约供 `peek_desktop_bridge` 与 Peek Desktop 共用；标准 `/` 仍为官方 Peek protocol v1。

## 路径与身份

- `GET /diagnostics/v1/capabilities`：只返回 `protocol: peek-desktop-diagnostics`、`version: 1`、`serverId` 和能力数组；无 token、配对码或记录。
- `ws://host:port/diagnostics/v1`：首个有效消息为 `diagnostics.hello`，10 秒内完成；所有消息为 JSON 文本。
- `hello` 字段：`protocol`、`version`、`serverId`、`deviceToken`、`runId`、可空的 `networkSessionId`。后三者来自同一官方 PeekRemote 实例的公开 API；不重新提交配对码。
- 返回 `diagnostics.welcome`，含 `runId`、`accepted`（emitterId 到已接纳十进制序号字符串的映射）；失败返回 `diagnostics.denied` 与 `reason`。
- 非空 networkSessionId 必须属于该已授权设备且当前在线；否则拒绝绑定。空值创建独立诊断运行，不按 App 名或时间猜测关联。重连的同一 device/run 不允许更换关联目标。
- 网络连接关闭、替换、服务停止或设备被忘记时，关闭对应诊断连接；关闭诊断授权不影响网络。

## 批次与确认

`diagnostics.batch` 包含 `emitterId` 与 `events`，一次 1–64 条，整条消息不超过 256 KiB；单事件不超过 128 KiB。事件字段见主同步方案，sequence 和 monotonicMicros 使用规范 uint64 十进制字符串（不带符号或前导零）。一个运行最多 16 个 emitter。

批次事件的 runId 和 emitterId 必须与连接和批次一致；同源序号从 1 递增。服务端先校验整个批次，再原子接纳；重放已接纳的序号不重复展示，新序号复用已有 eventId 或同批次序号冲突则拒绝。

返回 `diagnostics.ack`：`emitterId`、`sequence`，累计确认当前源的连续接纳位置。SDK 同一时刻最多保留一个待 ACK 批次，重连后以 welcome 中的确认位置重试有界队列。ACK 代表内存接纳，不代表持久化。

若 SDK 已淘汰某些事件，在发送后续序号前提交 `diagnostics.gap`：`emitterId`、`fromSequence`、`toSequence`、`reason`。范围必须覆盖服务端接下来期待的位置；服务端记录实际新增缺口后 ACK 到 toSequence，不用较新日志掩盖中间丢失。重复 gap 不重复计数。

非法自有消息返回 `diagnostics.error` 与 `reason`；未知消息忽略。`diagnostics.ping/pong` 用于存活检查，60 秒无输入关闭连接。与标准 Peek 无关的诊断失败不会关闭网络通道。

## 存储边界

桌面最多保留 8 个诊断运行，每运行 2,000 条/4 MiB 原文；优先淘汰低级别日志，异常和高等级日志仍受硬上限。显示接纳、去重、淘汰与缺口计数，最近 64 个 gap 范围可查询。确认位置独立于展示保留范围，不因 UI 淘汰回退 ACK。

SDK 初始队列同样限 2,000 条/4 MiB，50 ms 或 64 条触发发送；按字节限制批次。转换、脱敏与裁剪必须在入队前完成。停止/切换目标/上下文重置使旧的连接任务与 ACK 失效。
